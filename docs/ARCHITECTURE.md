# Architecture and module contracts

This is the contract that every module in the repository is written against. If you change a
signature here, change every caller in the same commit.

## Why save files

Every way people play Gen 1-5 today (cartridge dumps in emulators, RetroArch cores, phone
emulators, the decomp-based PC ports and static recompilations) ends in the same thing: a save
file that holds the cartridge's SRAM/flash image, sometimes with a small emulator trailer. Link
cables and Nintendo WFC do not survive that trip uniformly; save files do. So the widget never
talks to a running game. It reads and writes save files:

* **Home**: the browser parses the save locally, the player picks Pokémon, the raw records go to
  the server, the browser removes them from its copy of the save, and the player downloads the
  updated save and replaces their file. Withdrawing is the reverse.
* **Trading**: two players offer Pokémon that sit in their Home boxes; when both confirm, the
  server swaps owners in one transaction (applying trade evolutions) and both can withdraw.
* **Battling**: the server builds Showdown teams from Home Pokémon (or a save's party sent for
  the battle only) and runs the Pokémon Showdown simulator; the widget renders the protocol.

The save file itself never leaves the browser. Only individual Pokémon records do.

## Records: the unit that moves between saves, Home, trades and battles

A **record** is the canonical byte form of one Pokémon in a given format. It is what the server
stores and what saves accept.

| format | record bytes | notes |
|---|---|---|
| `pk1` | 33-byte box struct + OT name + nickname (11 + 11 international, 6 + 6 Japanese) | struct has no names in Gen 1/2 saves, so they travel with it |
| `pk2` | 1-byte list entry + 32-byte box struct + OT name + nickname (same sizes) | the list entry is the species, or 0xFD for an Egg: Gen 2 marks eggs only in the box/party species list |
| `pk3` | 80-byte box struct, encrypted exactly as stored in the PC | |
| `pk4` | 136-byte box struct, encrypted exactly as stored in the PC | |
| `pk5` | 136-byte box struct, encrypted exactly as stored in the PC | |

Party-only data (battle stats, current status) is not part of a record. Saves strip it when a
party Pokémon is taken and records are always inserted into PC boxes, where the game recomputes
stats on withdrawal. Each record carries metadata alongside it (never inside the bytes):
`{ format, lang, game }` where `lang` is `"en" | "ja" | "fr" | "de" | "it" | "es" | "ko"`.

### `shared/pkm/pkN.js` (one per format)

```js
export const FORMAT;            // "pk3"
export const GEN;               // 3
export const RECORD_SIZE;       // bytes for the default (international) language
export function recordSize(lang)              // pk1/pk2 differ for "ja"; others constant
export function parse(record, meta)           // -> Fields (plain JSON-able object, lossless)
export function build(fields, meta)           // -> Uint8Array record; build(parse(r)) === r byte-for-byte
export function toView(fields, meta)          // -> MonView
export function validate(record, meta)        // -> { ok: boolean, errors: string[], warnings: string[] }
```

`Fields` is format-specific and keeps every byte (unknown/padding bytes are kept as arrays) so the
round trip is exact. Checksums and encryption are recomputed by `build`.

### `MonView` (shared/pkm/view.js documents and normalises it)

```js
{
  format, gen, lang, game,               // game: origin game code when known ("E", "HGSS", ...)
  species, speciesName, form, formName,  // species = National Dex number
  nickname, isNicknamed, isEgg,
  level, exp, gender: "M" | "F" | null, shiny,
  nature, ability, abilityNum,           // null in Gen 1/2; abilityNum 0/1/2 (2 = hidden, Gen 5)
  heldItem,                              // item name or null
  moves: [{ id, name, pp, ppUps }],
  ivs: { hp, atk, def, spa, spd, spe },  // Gen 1/2: DVs (0-15) also exposed as dvs
  dvs, evs, statExp,                     // dvs/statExp only for Gen 1/2
  stats: { hp, atk, def, spa, spd, spe },
  friendship, pokerus, ball, markings,
  ot: { name, tid, sid, gender },
  met: { location, level, date, game } | null,
  ribbons: string[],
  pid, checksumOk, warnings: string[]
}
```

## Game data: `shared/data/`

Generated by `scripts/build-data.mjs` (committed output, plain `export const` JS modules so the
browser can import them without a JSON import attribute). `shared/data/index.js` is the only
module other code imports:

```js
export const MAX_SPECIES = { 1: 151, 2: 251, 3: 386, 4: 493, 5: 649 };   // also MAX_MOVE, MAX_ITEM, MAX_ABILITY per gen
speciesName(species, lang = "en")              // National Dex -> name ("Bulbasaur")
formName(species, form)                        // null for the base form
moveName(id), moveInfo(id, gen)                // -> { name, type, pp, power, category } as of that gen
itemName(gen, index)                           // item as stored in that gen's data (Gen 3 index space, Gen 2 index space...)
itemToNational(gen, index), itemFromNational(gen, nationalId)   // Gen 4+ item ids are "national"
abilityName(id), natureName(i)                 // nature order 0..24 = Hardy..Quirky
ballName(id), gameName(versionId), locationName(gen, id)
gen1ToNational(internal), nationalToGen1(species)       // Gen 1 internal index order
gen3ToNational(internal), nationalToGen3(species)       // Gen 3 internal index order (Hoenn 277+)
baseStats(gen, species, form)                  // { hp, atk, def, spa, spd, spe } (Gen 1: spa = spd = Special)
types(gen, species, form)
abilities(gen, species, form)                  // [slot0, slot1, hidden] ability ids (0 = none)
genderThreshold(species)                       // 0..254 (Gen 3+ PID low byte rule), 255 = genderless, also MALE_ONLY/FEMALE_ONLY flags
growthRate(species), expAtLevel(rate, level), levelAtExp(rate, exp)
evolutions(species)                            // [{ to, method: "trade"|..., item, gen }]
showdownId(species, form)                      // Showdown species id ("charizard", "unownb", ...)
```

`shared/pkm/stats.js`: `calcStats(gen, species, form, level, ivs|dvs, evs|statExp, nature)`,
`hiddenPower(gen, ivs)`, `gen2Gender(species, atkDV)`, `gen2Shiny(dvs)`, `unownLetterGen2(dvs)`,
`gen3Gender(species, pid)`, `gen3Shiny(pid, tid, sid)`, `unownFormGen3(pid)`, `natureFromPid(pid)`.

Text codecs (`shared/text/genN.js`): `decode(bytes, lang) -> string`, `encode(str, lang, maxBytes)
-> Uint8Array` (terminated and padded the way that generation pads), `canEncode(str, lang)`.

## Saves: `shared/saves/`

`index.js`:

```js
export function openSave(bytes, filename)  // -> SaveFile; throws FormatError with a user-facing message
export async function exportSave(save)     // -> Uint8Array with the container restored
```

`exportSave` is async because the Nintendo Switch Online Game Boy container stores a SHA-1 of
the payload (WebCrypto is async). `container.js` strips and remembers emulator trailers and
headers (MBC3 RTC footers, DeSmuME `.dsv` footer, NSO `SRAM` header, short or zero-filled PC-port
files) so `exportSave` restores them unchanged. A save from a PC port with its own non-cartridge
format (Gen1Recomp's Lua-table save) is refused with a message that names the port.

`genN.js` each export `detect(bytes) -> { game, lang, confidence } | null` and
`open(bytes, detection) -> SaveFile`. A `SaveFile` is:

```js
{
  gen, game, gameName, format, lang,
  trainer: { name, gender, tid, sid, money, playTime: { h, m, s } },
  boxCount, boxCapacity, currentBox,
  party(),                      // -> [{ record, meta, view }]
  box(i),                       // -> Array(boxCapacity) of { record, meta, view } | null
  boxName(i),
  takeFromParty(index),         // -> { record, meta }; refuses to remove the last non-egg Pokémon
  takeFromBox(box, index),      // -> { record, meta }; packed Gen 1/2 lists shift down
  putInBox(record, meta, box?, index?),  // -> { box, index }; first free slot when omitted
  registerDex(species, { form, gender, shiny, lang }),  // mark seen + caught
  serialize(),                  // -> Uint8Array (raw image, all checksums fixed)
  warnings: []
}
```

All mutations happen on an in-memory copy; nothing is written until `serialize()`.

## Conversions: `shared/pkm/convert.js`, `evolve.js`, `showdown.js`

```js
convert(record, meta, toFormat, { allowUnofficial, target: { game, lang }, now })
                                      // -> { record, meta, notes: [], provenance: { from, to, rule, at } }; throws FormatError if impossible
canConvert(meta, toFormat, { allowUnofficial, target })   // -> { ok, reason }
tradeEvolve(record, meta, { partnerSpecies })             // -> { record, meta, from, to, notes } | null
toShowdownSet(view, mechanicsGen, opts)                   // -> PokemonSet | throws FormatError if not representable
defaultName(species, gen, lang)                           // the name the game gives an un-nicknamed Pokémon
```

Official paths: pk1 <-> pk2 (Time Capsule), pk3 -> pk4 (Pal Park), pk4 -> pk5 (Poké Transfer).
Unofficial, opt-in per server (`UNOFFICIAL_TRANSFERS=1`, then a per-transfer checkbox, then a
permanent badge on the Pokémon): pk1/pk2 -> pk3 ("vc-model-v1", modelled on the Virtual Console
-> Gen 7 rules). Nothing ever converts down except pk2 -> pk1 when the Pokémon is Time Capsule
compatible. Conversions run lazily at withdrawal: Home keeps the original record until a
withdrawal commits, and provenance entries live next to the record, never inside its bytes.
Field-by-field rules: docs/research/data-and-transfers.md.

## Battles

`@pkmn/sim` (MIT) pinned to an exact version on the server only. Our own formats are registered
with `Dex.formats.extend()` (the stock `genNcustomgame` formats leak exact HP). `server/battles.js`
wraps each battle in a `BattleRoom` that splits the omniscient/spectator/p1/p2 channels, validates
choices, runs the turn timer and stores the input log so a restart can replay it.
`shared/battle/state.js` is a dependency-free protocol tracker used by the browser renderer, the
tests and the practice AI (`shared/battle/ai.js`). Battles never change stored Pokémon.
Details and tested snippets: docs/research/battle-engine.md.

## Sprites

`SPRITE_BASE` mirrors PokeAPI's `sprites/pokemon/` tree. Production self-hosts it at `/sprites/`
(`scripts/fetch-sprites.sh` fetches a pinned commit, about 24 MB of static PNGs, into `SPRITES_DIR`);
development points at raw.githubusercontent.com at the same pinned commit. jsDelivr refuses the
repository (package size limit).

## Server

* Auth: the widget asks the Matrix client for an OpenID token, the server verifies it against
  the user's homeserver (`/_matrix/federation/v1/openid/userinfo`) and issues a session cookie /
  bearer token. `DEV_AUTH=1` accepts the fake tokens from `web/dev/fake-matrix.html`.
* Storage: `node:sqlite`. Home Pokémon are stored as records plus a cached `MonView`; the server
  re-parses and validates every record it receives.
* REST for Home and trades, one WebSocket per widget for presence, trade updates and battles.

### Home API (`server/home.js`)

Records travel base64-encoded with their meta `{ format, lang, game }`. The server re-parses and
validates every record it receives (`pkN.validate`) and refuses bad checksums, impossible values
and a record whose fingerprint (sha256 of format + record) is already stored in anyone's Home.

```
GET  /api/home                      -> { boxes: [{ index, name, mons: [{ id, slot, format, game, lang, summary, locked }] }], boxCount, boxSlots: 30 }
GET  /api/home/mon/:id              -> { id, box, slot, format, lang, game, record, view, provenance: [], depositedAt, depositedBy, locked }
POST /api/home/deposit              { mons: [{ record, meta, box?, slot? }] } -> { stored: [{ id, box, slot }], warnings: [] }   (all or nothing)
POST /api/home/move                 { id, box, slot }   (swaps with whatever is there)
PUT  /api/home/box/:index           { name }
POST /api/home/withdraw/preview     { id, target: { format, game, lang }, allowUnofficial } -> { record, meta, view, notes, provenance }
POST /api/home/withdraw             { id, target, allowUnofficial } -> { record, meta, view, notes }   (removes it from Home; history keeps a copy)
POST /api/home/release              { id }
GET  /api/home/history?limit=50     -> { entries: [{ at, action, monId, detail }] }
```

A Pokémon locked by an open trade cannot be moved, withdrawn or released. Withdrawal converts
lazily (`convert`), and the browser puts the returned record into the open save with `putInBox`.

### Trade API (`server/trades.js`)

```
GET  /api/trades?roomId=            -> { open: [Trade], mine: [Trade] }   (open = offers in that room anyone may answer)
POST /api/trades                    { roomId, to: userId | null, offerMonId, wanted: { species?, note? } } -> Trade
POST /api/trades/:id/answer         { monId }        counter-offer (sets to_user for open offers); resets both confirmations
POST /api/trades/:id/confirm                         when both sides have confirmed the server swaps owners in one transaction
POST /api/trades/:id/cancel                          either side; unlocks both Pokémon
Trade = { id, roomId, status: open|answered|done|cancelled, from: { user, mon: summary }, to: { user, mon: summary } | null,
          wanted, fromOk, toOk, createdAt, updatedAt, result?: { evolved: [{ side, from, to }] } }
```

WebSocket pushes `{ type: "trade", trade }` to both parties (and to the room for open offers).
On completion each received Pokémon goes to the receiver's first free Home slot, and the trade
evolution of the record's own generation is applied (`tradeEvolve`). Battle team sources `home`
(`{ monIds }`, owned by the user) and `party` (`{ records: [{ record, meta }] }`, parsed for that
battle only) are registered by `server/battle-teams.js` through `registerTeamSource`.

## Widget (web/)

No build step. `index.html` loads the vendored `vendor/matrix-widget-api/api.min.js` (Apache-2.0,
licence kept beside it) and `js/widget-early.js` as classic scripts, because the Matrix client
sends its capabilities request on the iframe's load event and the WidgetApi must already be
listening; then `js/app.js` as a module.

* `js/matrix.js`: room id, verified-later display name, member list (handles `update_state`
  pushes and `readStateEvents`, merged by state key), OpenID token requests. URL parameters that
  still start with `$` are unsubstituted templates and count as absent.
* `js/api.js`: REST client (bearer token kept in memory, mirrored to sessionStorage when it
  works) and the WebSocket client (`hello`, `join`, request/reply by `rid`, reconnect).
* `js/auth.js`: widget -> OpenID; plain tab -> `#handoff=` code, bot DM code, or dev login.
* `js/ui.js`: DOM helpers, in-page dialogs (Element's sandbox has no `allow-modals`, so never
  `alert`/`confirm`/`prompt`), toasts, tabs.
* `js/savestore.js`: the saves the player opened and their unsaved changes; storage inside a
  widget iframe is partitioned or ephemeral, so IndexedDB is best-effort and the UI always offers
  the download. Downloads use a Blob `<a download>` from a click.
* `js/views/{saves,home,trade,battle}.js`: one module per tab, each `export function mount(el, app)`.
* `web/dev/fake-matrix.html`: two widgets (Alice, Bob) under a fake client that answers
  capabilities, `get_openid` (two-phase), `update_state` and room events; run with `DEV_AUTH=1`.
